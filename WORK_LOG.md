## 📅 Session Log: 2026-11-25

### Objective: Billing, Invoices & HITL Refund System Implementation
* **Files Created & Modified:**
  * `app/schemas/billing.py`: Decimal-precision Pydantic schemas for `InvoiceResponse`, `ApproveRefundRequest`, `ApproveRefundResponse`, `RefundRequest`, and `RefundResponse`.
  * `app/api/v1/invoices.py`: Invoices queries and complete Human-In-The-Loop (HITL) refund execution pipeline.
  * `app/main.py`: Registered `invoices_router` into FastAPI application factory (13 total registered routes).
* **Security & Defense-in-Depth Mechanisms:**
  1. *Dual-Layer Idempotency:* Fast Redis key lookup with durable PostgreSQL `audit_logs` fallback; identical requests return cached execution replay.
  2. *Cryptographic HITL Tokens:* Refunds > $100 require a 15-minute signed HMAC-SHA256 token generated by an admin with `refund.issue` (`POST /invoices/{id}/approve-refund`).
  3. *Replay & Tamper Protection:* Approval signature binds invoice ID, amount, org ID, approver ID, and expiry timestamp; single-use consumption is enforced against `audit_logs`.
  4. *Fixed-Point Financial Integrity:* Validates remaining balance (`amount <= invoice.amount - invoice.refunded_amount`) using Python `Decimal` / PostgreSQL `NUMERIC(10, 2)`.
  5. *Concurrency Safety:* Applies `SELECT ... FOR UPDATE` row locks to prevent simultaneous double-refund race conditions.
